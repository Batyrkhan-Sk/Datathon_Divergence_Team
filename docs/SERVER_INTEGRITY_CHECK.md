# Изолированная проверка на сервере

Пакет `FORTE_INTEGRITY_CHECK.pyz` проверяет совместимость исправлений с кодом
в `/home/jovyan/work/forte_datathon`. Он не выкатывает изменения на сайт.
Сначала создаётся копия исходного кода, затем отдельная копия с исправлениями.
Тесты используют только искусственные видео и тестовый анализатор.

## Что запускать в Jupyter

1. В файловом браузере Jupyter открой `work` и загрузи туда
   `FORTE_INTEGRITY_CHECK.pyz` кнопкой Upload Files.
2. Открой **File → New → Terminal** и выполни одну команду:

```sh
/home/jovyan/work/forte_nic_stage1_Vte6HDi1/forte-nic-clean-py313/bin/python -I -B \
  /home/jovyan/work/FORTE_INTEGRITY_CHECK.pyz \
  --project /home/jovyan/work/forte_datathon
```

Этот Python уже использовался для предыдущих серверных проверок. Нужен Python
3.12 или новее. Если указанный интерпретатор отсутствует, ничего не установится:
для другого существующего Python 3.12+ достаточно заменить первую часть команды.
Не нужно запускать `activate`, устанавливать пакеты в base или останавливать
работающий сервис.

В начале команда напечатает путь новой папки вида
`/home/jovyan/work/forte-integrity-check-<случайный суффикс>`. В конце —
`report_path` и содержимое `REPORT_SAFE.json`. Можно прислать этот JSON или
текст терминала от первой строки `{` до конца. Приватные логи из `private_logs`
отправлять не требуется.

## Действия пакета

- Сверяет хеши 30 выбранных исходных файлов с полученным серверным отчётом.
  Отдельно допускается неизменённый снимок `main` для локальной репетиции.
  Изменённый или неизвестный снимок останавливает проверку до установки пакетов
  и запуска тестов. Это не полная инвентаризация репозитория.
- Создаёт новую папку рядом с проектом, вне него. Повторный запуск создаёт ещё
  одну новую папку. Существующие папки не переиспользуются и не удаляются.
- Копирует только перечисленные исходники, статические файлы интерфейса и
  `data/rules.json`. `.env`, данные клиентов, веса, кеши, база заданий, логи
  сайта и ноутбуки не копируются и не читаются.
- В `candidate` заменяет только функции проверки результата, извлечения кадров
  и чтения видео в трёх файлах. Остальные скопированные файлы сохраняются
  побайтно; окружающие определения в этих трёх файлах также сохраняются.
  `candidate.patch` содержит точный локальный diff для ревью. Содержимое
  заменяемых функций изменяется намеренно и требует ревью перед переносом.
- Создаёт новую `.venv` без системных пакетов. Устанавливает фиксированные
  тестовые зависимости из PyPI только в неё, без pip-кеша. Нужен доступ к PyPI.
  Torch, Transformers, Uvicorn и модельные веса не устанавливаются.
- Выполняет семь одинаковых синтетических проверок до/после, затем 86 тестов
  исправленного результата и evaluator. API проверяется через TestClient в
  памяти, без запуска HTTP-сервера и занятия порта. Для проверки очереди
  создаются только собственные тестовые дочерние процессы.
- В тестовых процессах запрещает TCP bind/connect, DNS и импорт моделей,
  скрывает GPU, ограничивает CPU-пулы одним потоком. Проверяет работу этих
  запретов перед тестами. Это дополнительная защита, не системный контейнер.
- Проверяет, что исходные 30 файлов не изменились за время работы. Изменения,
  сделанные параллельно тиммейтом, не отменяются и не перезаписываются: такой
  запуск получает отдельный неуспешный статус.

Скрипт не использует команды остановки/перезапуска сайта, не обращается к ngrok,
не читает список чужих процессов и не меняет git-состояние. Зависимости
существующих окружений остаются на месте. Временная папка, окружение, diff и
логи сохраняются для проверки; автоматической очистки нет.

## Как читать результат

Успешная проверка требует всех условий:

- `status: passed`;
- `original_files_still_identical: true`;
- `other_copied_source_files_byte_identical: true`;
- `tests.passed: 86`, `tests.failed: 0`, `tests.skipped: 0`;
- `five_invalid_cases_rejected: true`, `valid_controls_preserved: true`.

`stopped`, `failed`, `interrupted` или `source_changed_during_check` не считаются
успехом. По `reason` и `phase` можно понять, где остановилась проверка. При
остановке не нужно удалять данные или чинить окружение тиммейта.

Успех доказывает совместимость скопированного кода с исправлениями в новом
тестовом окружении. Он не доказывает рост точности модели, равенство зависимостей
работающему сайту, время полного GPU-запроса или актуальность нормативных ссылок.
После проверки патч остаётся кандидатом для ревью и отдельного прогона модели.
Автоматического переноса в исходный проект нет.

## Сборка пакета

Исходники сборщика и проверки находятся в `tools/server_integrity_check`.
Входной отчёт используется только для ожидаемых хешей кода. В архив включаются
исправления, синтетические тесты и lock-файл зависимостей; банковских данных нет.

```sh
python tools/server_integrity_check/build.py \
  --main-snapshot /local/path/to/unchanged-main \
  --server-report /local/path/to/safe-server-report.txt \
  --output /local/path/to/FORTE_INTEGRITY_CHECK.pyz
```
