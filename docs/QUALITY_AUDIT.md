# Проверка качества моделей и надёжности результатов

Вклад этой ветки — воспроизводимая оценка модели и защита от недостоверного
результата сервиса. Детекторы тиммейта не переписаны. Инструмент позволяет
проверять их изменения на одинаковых данных и видеть пропуски, ложные тревоги,
ошибки обработки и задержку отдельно. Это реализованный код, но ещё не новый
замер качества распознавания на GPU.

## Что уже сделано

- `eval/quality_audit.py`: подготовка набора, запуск локального анализатора,
  сохранение прогресса после каждого файла и сравнение двух отчётов.
- `eval/quality_metrics.py`: отдельный расчёт качества обнаружения, временной
  локализации, командных типов событий, полноты обработки и времени.
- Проверка бинарной разметки и секунд CSV по официальному XLSX. Типы событий,
  уверенность в типе и группы остаются командными аннотациями.
- Дедупликация по SHA-256 содержимого. При конфликте одинаковых записей спорное
  поле становится неизвестным для соответствующей метрики; согласованные поля
  остаются пригодными для оценки.
- Привязка отчёта к хешам исходников, данным и разметке. Изменение кода после
  подготовки требует нового manifest. Перед обработкой повторно проверяется
  хеш видео. Сравнение проверяет полноту сохранённых записей, их метки, расчёты
  и одинаковую версию формул метрик.
- Анализатор получает только путь видео. Метки, типы и правильные секунды ему
  не передаются. Старый кеш детекций `ML_OBJECTS_CACHE` отклоняется: его связь
  с текущими входами и моделью не подтверждена.
- Частные отчёты и логи создаются с правами `0600`; Python и нативные stdout/
  stderr анализатора направляются в локальный лог. CLI выводит только агрегаты.
  Существующие выходные файлы не перезаписываются.

Связанные изменения API и извлечения кадров описаны в
[RESULT_INTEGRITY.md](RESULT_INTEGRITY.md): некорректный результат и отсутствие
доказательного кадра приводят к ошибке обработки; кадр перечитывается из
загруженного видео, возвращается фактическое время декодера.

## Почему метрики разделены

Ошибка, отсутствующий файл, незавершённая обработка и некорректный ответ не
считаются ответом «нарушений нет». Для них сохраняется неизвестный исход.
Пропуск нарушения — отдельный случай: обработка завершилась, но модель дала
отрицательный ответ на положительный пример.

Accuracy среди завершённых заданий показывается вместе с долей обработанных
файлов и долей правильных ответов среди всех запрошенных примеров. Полнота
обнаружения и локализации также показывается относительно всех пригодных для
соответствующей оценки положительных записей. Например, один найденный точно
вовремя эпизод из десяти даёт 100% по времени среди найденных, но лишь 10%
среди всех десяти положительных записей.

Допуски времени ±1/±2/±5 секунд и окно типа ±3 секунды — диагностика этой
реализации, а не правила жюри. Официальная таблица не содержит полной разметки
всех событий каждого видео; полная событийная precision/recall не заявляется.
Метрика типов основана только на уверенных командных аннотациях с однозначным
временем и не подтверждает правильность нормативной квалификации.

Ответ позже 300 секунд получает статус `over_budget` и не входит в успешные
результаты в пределах бюджета. Процесс принудительно не прерывается. Измеряется
время хеширования входа и вызова pipeline; загрузка моделей записывается отдельно.
Загрузка файла через HTTP, очередь и повторная обработка результата backend в
этот замер не входят. Проверка полного ограничения ТЗ требует отдельного API-
замера на сервере.

## Запуск

Команды выполняются из корня отдельной рабочей копии. Для подготовки достаточно
Python 3.11+ и `openpyxl`. Для тестов используются зависимости backend, NumPy и
OpenCV. Для инференса требуется отдельное окружение с ML-зависимостями проекта
и уже сохранёнными весами. Пакеты в серверную base-среду не устанавливаются.

Подготовка не импортирует модели, не декодирует и не выводит кадры:

```sh
.venv/bin/python -m eval.quality_audit prepare \
  --video-dir /absolute/local/path/to/videos \
  --output out/quality-audit/manifest-run-01.json
```

По умолчанию сверяются `data/labels.csv` и `data/open_labels.xlsx`; для другой
копии предусмотрены `--labels` и `--official-labels`. Manifest содержит частные
пути и разметку, поэтому остаётся в разрешённой среде. При переносе на сервер
нужно заново подготовить manifest в отдельной копии с серверными путями.

Настройки модели выбираются явно для конкретного эксперимента. Например,
следующая команда запрашивает VLM; доступность памяти и свободной GPU проверяется
перед запуском, чужие процессы не останавливаются:

```sh
ML_USE_VLM=1 .venv/bin/python -m eval.quality_audit run \
  --manifest out/quality-audit/manifest-run-01.json \
  --output out/quality-audit/report-run-01.json
```

Инструмент включает offline-режим Hugging Face/Transformers. Это не сетевой
песочник: разрешённая среда и локальный характер подключаемого анализатора
проверяются отдельно. Недоступные веса дают ошибку загрузки модели, а не
отрицательные предсказания. Фактическая версия весов пока не подтверждается
хешами; отчёт явно содержит `runtime_model_and_weights_verified: false`.

Сырые диагностические сообщения сохраняются рядом в `*.private.log`. JSON-
отчёт содержит построчные предсказания и разметку. Оба файла остаются локальными,
их нельзя добавлять в git или отправлять в чат. Каталог `out/` уже исключён из git.
При прерывании последняя сохранённая версия сохраняет незавершённые задания;
автоматического продолжения с середины пока нет.

После изменений кода создаются новые manifest и отчёт с новыми именами:

```sh
.venv/bin/python -m eval.quality_audit compare \
  --left out/quality-audit/report-run-01.json \
  --right out/quality-audit/report-run-02.json
```

Сравнение не запускает модели. Разницу метрик оно рассчитывает только при
одинаковых входах, оценочных метках и коде формул. Статус завершения обоих
прогонов выводится отдельно: незавершённый прогон не доказывает превосходство
модели. Исторические отчёты другого формата автоматически не конвертируются.

Коды завершения: `0` — команда выполнена; `1` — запуск завершён с неполной
обработкой или отчёты несопоставимы; `2` — ошибка входов/подготовки. Подготовка
сохраняет отсутствующие файлы в manifest и показывает их число; последующий
запуск учитывает их как `missing`.

## Что ещё не подтверждено

Новый полный прогон GPU-модели, её фактические веса и настройки, качество после
изменений, задержка полного API и актуальность всех нормативных оснований РК.
Данные C и E уже встречались при разработке/оценке, независимым тестом они не
объявляются. Лучшие исторические метрики не переносятся на эту ветку.

Таблица рекомендуемых моделей из командной переписки не является доказательством
внедрения: в проверенных исходниках есть RT-DETRv2, OWLv2 и подключаемый Qwen3-VL;
импорты ByteTrack и RTMPose/RTMW не найдены. Дополнительные функции второй ветки
не дают оценки точности основной модели.

Предлагаемая зона ответственности участника этой ветки: **качество моделей и
надёжность результатов**. Демонстрируемый результат — тестируемый инструмент
оценки, проверка данных и обработка ошибочных ответов, а не заявление о новом
обучении или выросшей точности.
